# Novel Plot Composer

小説のプロットをグラフィカルに構成するデスクトップアプリ。
ブレイク・スナイダー・ビート・シート（BS2）の縦タイムラインを画面の中心に置き、
「どの位置で何が起きるか」を目で確かめながら組み立てる。

## できること

- **縦タイムライン** — 物語全体を 0〜100% の帯で表し、点のビート（ミッドポイントなど）は左、
  幅を持つ区間（お楽しみ、フィナーレなど）は右に並ぶ。ラベルは上下にドラッグして動かせる。
  区間は上下の端をドラッグで伸縮する。
- **4 つの構成テンプレート** — BS2 / 三幕構成 / 起承転結 / ヒーローズ・ジャーニー。
  切り替えても、書いた内容は消えない（同名のビートには引き継ぎ、対応がないものも中身があれば残す）。
- **目安文字数** — 想定総文字数を入れると、各ビートの尺から目安字数を割り出す。書いた量と並べて表示する。
- **登場人物とサブプロット** — 人物をビートに紐づけられる。B ストーリーなどの並走する線は、
  タイムライン脇に色付きの帯として重なる。
- **保存と書き出し** — `.novelplot`（JSON）で保存。Markdown（構成表）と執筆用テキストに書き出せる。
- 自動保存、Undo / Redo（ドラッグ 1 回はまとめて 1 ステップ）、ライト / ダークの自動切り替え。

## なぜ Electron か

やりたいことが「手元のファイルを開いて書いて保存する」道具なので、Electron を選んだ。

- ローカルファイルのダイアログ・ネイティブメニュー・ファイル関連付け（`.novelplot`）が素直に書ける
- 日本語入力（IME）とフォント周りで踏む地雷が少なく、Windows / macOS の両方で同じ挙動になる
- Tauri のほうが配布サイズは小さいが Rust ツールチェインが要る。この規模では割に合わない

ただし**描画側（renderer）は Electron に一切依存させていない**。
`window.api` がある場合だけ IPC を使い、無ければブラウザの機能に落ちる。
そのため `npm run web` でそのままブラウザ版としても動くし、
後から Tauri や Web アプリに載せ替えることになっても、UI はそのまま持っていける。

## 開発

```bash
npm install
npm run dev        # Electron で起動
npm run web        # ブラウザで起動（保存はダウンロード、読み込みはファイル選択）
npm run typecheck
npm run build
npm run dist:win   # / dist:mac — インストーラを作る
```

## 構成

```
src/
  main/      Electron メインプロセス（ウィンドウ、メニュー、ファイル IPC）
  preload/   contextBridge で renderer に渡す API
  renderer/
    src/lib/         型・テンプレート・プロジェクト操作・書き出し・履歴
    src/components/  タイムライン / インスペクタ / 左パネル / ツールバー
```

データはすべて `Project` 1 つの JSON に入る（`src/renderer/src/lib/types.ts`）。
ビートは `start` / `end` を 0〜100 の位置で持ち、`kind` が `point` なら `start === end`。

## 操作

| したいこと | 操作 |
| --- | --- |
| ビートを選ぶ | ラベルをクリック |
| 位置を変える | ラベルを上下にドラッグ |
| 区間を伸縮する | 帯の上端・下端をドラッグ |
| ビートを足す | 目盛りをダブルクリック、または「＋ ビート」 |
| 保存 / 開く | Ctrl (Cmd) + S / O |
| 元に戻す / やり直し | Ctrl (Cmd) + Z / Shift + Z |
